# 图片节点历史与 Agent 控制设计

## 目标

修复图片生成历史选择、下游重复引用和 Agent 参数控制，同时统一节点标题与尺寸显示。

## 已确认行为

1. 图片节点生成多个结果后，历史选择按钮与放大、下载按钮在节点上方水平排列。
2. 点击历史选择按钮打开节点下方的缩略图菜单；缩略图约为当前节点宽度的一半，不打开大图预览。
3. 选中历史图片后，节点显示该图片，菜单收起，下游只接收当前选中的一张图片。
4. 生成历史节点使用当前 `image` 作为下游首选；单独上传图片仍只传递上传图片，不展开为历史列表。
5. Agent 只有在用户明确指定节点时才修改已有节点。未指定节点时创建新节点。
6. Agent 能将自然语言中的模型、尺寸、比例和清晰度转换为节点参数；未明确要求时不执行自动排版。
7. 节点标题按类型和序号显示，例如“图片节点1”“文本节点1”；右上角显示实际尺寸，例如“1280 × 720”。

## 实现边界

- 继续使用现有发布版 `dist/assets/index-v1514-gemini-strict-sizefix-v6.js`、节点 CSS 和 Agent 补丁，不引入新依赖。
- 在画布数据流入口统一去重并优先当前图片，避免只在某一个缩略图组件中修复。
- Agent 保持现有 JSON action 协议，增加明确的节点更新动作与参数字段；系统提示明确禁止隐式 `layout`。
- 通过静态回归测试覆盖 DOM 合同、数据优先级、Agent action 合同和节点显示规则。

## 验收标准

- 生成两张图后，历史按钮位于节点上方操作栏，历史面板中的每个缩略图不超过节点宽度的一半。
- 选择图1后，下游节点的 `upstreamImages` 恰好为 `[图1]`，提示词引用列表也只有图1。
- 上传图片后下游仍只收到一张上传图片。
- Agent 未被要求排版时不返回或执行 `layout`；明确指定节点时生成 `updateNode`，未指定时生成新节点。
- 图片、文本、视频等节点显示稳定的类型序号和尺寸信息。
